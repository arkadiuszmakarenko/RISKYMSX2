Chapter 26: Flexible Static Memory Controller (FSMC)

The Flexible Static Memory Controller (FSMC) supports multiple static memory types and a rich set of memory operation methods. It can be used to expand different types of large-capacity static memories according to system application requirements.

26.1 Main Features

  • Supports operation of SRAM, ROM, NOR FLASH, and PSRAM
  • Supports operation of NAND FLASH with built-in hardware ECC, capable of detecting up to 8 KByte of data
  • Supports operation of synchronous devices, such as PSRAM
  • Supports 8-bit or 16-bit data bus width
  • Timing signals are software-programmable

26.2 Functional Description

26.2.1 Module Structure

The FSMC mainly consists of the HB bus interface, NOR memory controller, NAND memory controller, and external device interface.

26.2.3.4 NOR/PSRAM Synchronous Transfer Address/Data Multiplexed Timing Diagrams

Note the data delay and NOR FLASH latency: the DATLAT value must be consistent with the definition in the NOR FLASH configuration register. The clock cycles when the NADV signal is low are not counted in the delay parameter. The FSMC DATLAT parameter can be DATALAT+2 or DATALAT+3. For special memories that generate an NWAIT signal during the data hold time, DATLAT must be set to the minimum value. For other memories that do not generate an NWAIT signal during the data hold time, the data hold time of the FSMC and the memory must be set consistently.

For single bulk transfers, note that the memory is configured in synchronous burst mode. If 16-bit data is transferred, the FSMC performs one burst transfer of length 1. If 32-bit data is transferred, the FSMC splits it into two 16-bit transfers and performs one burst transfer of length 2.

During NOR FLASH synchronous burst mode access, after the hold time (DATLAT+1 CLK), if the NWAIT signal is detected as low, the FSMC must insert wait cycles before the NWAIT goes high. When the NWAIT becomes high, the FSMC considers the data valid. During the wait state insertion controlled by the NWAIT signal, the controller continuously sends clock pulses to the memory, maintains the chip select signal and output enable signal, and ignores invalid data signals. In burst transfer mode, the NWAIT signal of the NOR FLASH can select two timing configurations by configuring the WAITCFG bit.

26.2.4.4 NAND FLASH Operation Flow

The NAND FLASH command latch enable signal (CLE) and address latch enable signal (ALE) are driven by FSMC address lines A16 and A17, respectively. Therefore, when sending commands or addresses to NAND FLASH, a write operation must be performed to a specific address in the memory space. The NAND FLASH read operation process is as follows:

  1. According to the characteristics of the NAND FLASH to be operated, configure the PWID, PTYP, PWAITEN, and PBKEN of the FSMC_PCR2, FSMC_PMEM2, and FSMC_PATT2 registers.
  2. Write the command byte to the common memory space. During the period when NWE is low, CLE outputs a high level. At this time, the command byte is recognized by the NAND FLASH as a command and latched. The subsequent page read operation does not need to repeat sending this command.
  3. Then write 4 bytes to the memory space as the start address for the read operation. During the period when NWE is low, ALE outputs a high level. At this time, the 4 bytes are recognized by the NAND FLASH as the start address for the read operation. When operating the attribute memory space, the FSMC can generate different timing to implement the pre-wait function of some NAND FLASH devices.
  4. Before starting a new operation, the FSMC controller must wait for the NAND FLASH R/NB signal to go high. During the wait period, the FSMC controller must keep the NCE signal low.
  5. The FSMC controller can read out the memory page byte by byte from the NAND FLASH by operating the common memory space.

26.2.4.5 NAND FLASH Pre-wait Function

Certain special NAND FLASH devices require the R/NB signal to go low after the last address byte is input, as shown in Figure 26-16.

In the figure: (1) CPU writes command byte 0x00 to 0x70010000; (2) CPU writes NAND FLASH address A7–A0 to 0x70020000; (3) CPU writes NAND FLASH address A15–A8 to 0x70020000; (4) CPU writes NAND FLASH address A23–A16 to 0x70020000; (5) CPU writes NAND FLASH address A31–A24 to 0x70020000.

When using this function, configure the MEMHOLD field of the FSMC_PMEM2 register to guarantee the tWB timing. After that, for all read/write operations to the NAND FLASH, the FSMC controller inserts (MEMHOLD+1) HCLK hold delay between the rising edge of the NWE signal and the next operation. To solve this issue, use the attribute space to configure the ATTHOLD value to meet the tWB timing, while keeping MEMHOLD at the minimum value. In this case, only when writing the last byte of the NAND FLASH address does the FSMC controller need to write to the attribute memory space; all other NAND FLASH read/write operations use the common memory space.

26.2.4.6 NAND FLASH ECC Function

The FSMC NAND FLASH controller includes a hardware error correction code (ECC) calculation module, which can effectively reduce the software workload on the CPU when processing error correction codes. The ECC module supports correcting 1-bit errors and detecting 2-bit errors per 256, 512, 1024, 2048, 4096, or 8192 bytes during NAND FLASH read/write operations. The valid ECC result bits corresponding to page sizes are shown in Table 26-30. After the ECC calculation circuit is enabled, the ECC module monitors the NAND FLASH data bus and read/write signals (NCE and NWE). Notes for using ECC:

  • When accessing NAND FLASH, data appearing on the D[15:0] bus is latched and used for ECC calculation.
  • After the specified number of bytes has been written to or read from NAND FLASH, the software reads the ECC value from the FSMC_ECCR2 register. To recalculate ECC, first clear ECCEN to 0, then write 1 to re-enable ECC calculation.
