Chapter 23: Digital Video Port (DVP)

The Digital Video Port (DVP) is used to connect to camera modules to acquire image data streams. It provides an 8/10/12-bit parallel interface for communication and supports a maximum pixel clock input frequency of 150 MHz. It supports image data organized in raw line and frame formats, such as YUV, RGB, etc., and also supports compressed image data such as JPEG format. It can receive high-speed parallel data streams output by external 8-bit, 10-bit, and 12-bit camera modules. During reception, synchronization is primarily achieved through VSYNC and HSYNC signals. Image cropping functionality is supported.

23.1 Main Features

  • Configurable 8/10/12-bit data width mode
  • Supports YUV and RGB format data
  • Supports JPEG compressed format data
  • Built-in FIFO, supports DMA transfer
  • Supports double-buffer reception
  • Supports cropping function
  • Supports continuous mode and snapshot mode

23.2 Functional Description

23.2.1 Connecting to the Sensor

  • PCLK (Pixel clk): Pixel clock; each clock corresponds to one pixel of data (uncompressed data). The maximum supported HCLK clock frequency output by the external DVP interface sensor is 150 MHz.
  • HSYNC (horizontal synchronization): Line synchronization signal.
  • VSYNC (vertical synchronization): Frame synchronization signal.
  • DATA: Pixel data or compressed data; bit width supports 8/10/12 bits.
  • XCLK: Reference clock for the sensor; can be provided by the microcontroller or externally, typically using a crystal oscillator.
  • I2C interface: Used to configure the sensor's registers; can be implemented by bit-banging I2C timing through ordinary GPIO pins, or by using the hardware I2C interface.

As shown in Figure 23-2, the sensor internally has a complete image size of 3576×1145. After internal scaling processing, the image data size finally output from the interface is 1920×1080, with an image refresh rate of 25.

HCLK is the time for one pixel transfer, so HSYNC is 3576 times HCLK. Among the 3576 pixels, only 1920 pixels are valid; during the remaining 1656 pixel periods, the sensor does not transmit data. VSYNC is the frame synchronization signal, so the VSYNC period is 3576×1145 times HCLK. Similarly, only during the 1920×1080 valid pixel periods does the sensor transmit data. If the sensor transmits JPEG compressed data, the HSYNC signal may not be needed.

The relationship between DVP interface signals and image data is primarily based on the datasheet of the selected sensor.

23.2.3 RGB/YUV/JPEG Compressed Data Format Description

  • RGB
    Three primary colors: red, green, blue.
  • YUV
    Luminance signal Y, chrominance signals U and V, Pb and Pr, Cb and Cr.
  • JPEG (Joint Photographic Experts Group)
    Lossy compression, but the lost portions are those not easily perceived by human vision. It exploits the characteristic that the human eye is insensitive to high-frequency information in computer color. It removes visually redundant information (spatial redundancy) and removes inherently redundant information in the data (structural redundancy).

23.3 Digital Video Port Application

23.3.1 DVP Configuration Description

  1. In DVP data reception, each frame of data is stored alternately in BUF0 and BUF1, starting from BUF0. For RGB and YUV data streams, the hardware resets and selects BUF0 to start each time the frame signal transitions from inactive level to active level. When one row of data is filled, it switches to BUF1, achieving alternate storage. For JPEG compressed data, the hardware sets the switching threshold between BUF0 and BUF1 based on the configured DMA reception length.
  2. When the data bus width is 10 bits or 12 bits, each time a data is received, the system automatically performs unsigned extension to 16 bits before storing.
  3. The R16_DVP_ROW_NUM and R16_DVP_COL_NUM registers must match the actual image size output by the sensor.
  4. In video stream RGB mode, R16_DVP_COL_NUM represents the number of valid HCLK periods in one row of data, and R16_DVP_ROW_NUM represents the number of rows contained in one frame of image data. In image JPEG mode, R16_DVP_COL_NUM is used to configure the DMA length; in this mode, the R16_DVP_ROW_NUM register has no effect.

23.3.2 DVP Application Description

When using the digital video port to receive image data, the DVP-related control registers must be correctly configured to match the mode of the image sensor. The specific operation steps are as follows:

  1. Clear the RB_DVP_ALL_CLR and RB_DVP_RCV_CLR fields through the R8_DVP_CR1 register.
  2. Configure the image mode, data bit width, HCLK polarity, HSYNC polarity, and VSYNC polarity through the R8_DVP_CR0 register to match the SENSOR output.
  3. Based on the valid image pixels output by the configured image sensor, configure the R16_DVP_ROW_NUM and R16_DVP_COL_NUM registers to match the SENSOR output. In image JPEG mode, only the R16_DVP_COL_NUM register needs to be configured.
  4. Configure the DMA receive address through the R32_DVP_DMA_BUF0/1 registers.
  5. If using snapshot mode, configure the RB_DVP_CM field through the R8_DVP_CR1 register to enable snapshot mode.
  6. If using cropping mode, configure the RB_DVP_CROP and RB_DVP_FCRC fields through the R8_DVP_CR1 register to enable the cropping function and control the frame capture rate. At the same time, configure R16_DVP_HOFFCNT, R16_DVP_VST, R16_DVP_CAPCNT, and R16_DVP_VLINE to set the cropped image dimensions.
  7. As needed, enable the corresponding interrupts through the R8_DVP_IER register, and configure the interrupt priority and enable the DVP interrupt through the interrupt controller (PFIC).
  8. Enable DMA through the R8_DVP_CR1 register, and enable the DVP interface through the R8_DVP_CR0 register.
  9. Wait for the relevant reception interrupts to be generated and process the received data in a timely manner.

23.3.3 Capture Mode Description

The DVP interface supports two capture modes: snapshot (single frame) mode and continuous mode.

23.3.3.1 Snapshot Mode

In this mode, only a single frame is captured (RB_DVP_CM set to 1 in the R8_DVP_CR1 register). After the DVP interface is enabled, the system waits for the frame start to be detected, then begins image data sampling. After receiving a complete frame of data, the DVP interface is turned off (the RB_DVP_ENABLE field in the R8_DVP_CR0 register is cleared to 0). The single-frame capture waveform in snapshot mode is shown in Figure 23-3.

23.3.3.2 Continuous Mode

In this mode (RB_DVP_CM cleared to 0 in the R8_DVP_CR1 register), after the DVP interface is enabled, each frame of data is continuously sampled until the RB_DVP_ENABLE field in the R8_DVP_CR0 register is cleared to 0. The frame capture waveform in continuous mode is shown in Figure 23-4.

23.3.4 Cropping Function Description

The DVP can use the cropping function to extract a rectangular window from the received image. The rectangular window's starting coordinates (the rectangle's top-left X coordinate R16_DVP_HOFFCNT, Y coordinate R16_DVP_VST) and window size (R16_DVP_CAPCNT for horizontal size, R16_DVP_VLINE for vertical size) are configurable.
